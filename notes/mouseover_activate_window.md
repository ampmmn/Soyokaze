# カーソル位置によるアクティブ切替

## 概要

アプリケーション設定の「カーソル位置によるアクティブ切替」を有効にすると、メインウインドウにカーソルが入った後、カーソルがメインウインドウの外へ出たタイミングでメインウインドウを非アクティブにする。

また、いったん外へ出た後に再びメインウインドウ内へ入ると、メインウインドウをアクティブにする。

この機能は、マウスカーソルを使ってランチャーを一時的にアクティブにする用途を想定している。初回のカーソル侵入ではアクティブ化・非アクティブ化を行わず、侵入したという状態だけを記録する。

## 実装構成

### MouseoverActivateWindow

`MouseoverActivateWindow` は、カーソル位置を一定間隔で監視するための非表示の子ウインドウである。

`LauncherMainWindow::OnInitDialog()` でメインウインドウを親として生成する。タイマーはこの子ウインドウのウインドウハンドルに対して設定するが、カーソル判定の対象は親ウインドウである。

設定値 `Soyokaze:IsMouseoverActivate` は `AppPreference::IsMouseoverActivate()` から取得する。設定変更時は `AppPreferenceListenerIF` の通知を受け、設定が有効ならタイマーを開始し、無効なら停止する。

タイマー間隔は現在 `100ms` で、`MouseoverActivateWindow.cpp` の `TIMER_INTERVAL` で定義している。

### LauncherMainWindowとの関係

依存関係は次の一方向になっている。

```text
LauncherMainWindow -> MouseoverActivateWindow
```

`MouseoverActivateWindow` は `LauncherMainWindow` のクラス定義を参照しない。メインウインドウのハンドルを `Create()` 時に受け取り、Win32 API でそのウインドウの状態と領域を確認する。

## カーソル判定

タイマー処理では、次の順で判定する。

1. 親ウインドウが有効かつ表示中か確認する
2. `GetCursorPos()` でスクリーン座標のカーソル位置を取得する
3. 親ウインドウのクライアント領域を取得する
4. カーソル位置を親ウインドウのクライアント座標へ変換する
5. `CRect::PtInRect()` で領域内か判定する

判定結果は次の2つの状態で管理する。

- `mHasEntered`: 監視開始後に一度でもメインウインドウ内へ入ったか
- `mWasInside`: 直前のタイマー処理時点でカーソルが領域内だったか

`mHasEntered` が `false` の間は、カーソルが領域内に入っても状態を記録するだけである。これにより、機能を有効にした瞬間からカーソルがウインドウ内にある場合に、いきなりアクティブ化・非アクティブ化されることを防いでいる。

`mHasEntered` が `true` になった後は、次のように処理する。

| 現在の位置 | 前回の位置 | 処理 |
| --- | --- | --- |
| 内側 | 外側 | `SetForegroundWindow()` でメインウインドウをアクティブ化 |
| 外側 | 内側 | メインウインドウが前面なら、次の表示中ウインドウを前面化 |
| 変化なし | 変化なし | 何もしない |

外へ出たときは、メインウインドウが現在の前景ウインドウである場合だけ非アクティブ化を行う。切り替え先は `GetNextHwnd()` で取得した、現在の前景ウインドウの次にある表示中ウインドウである。

## 状態リセット

`ResetState()` は次の状態を初期状態へ戻す。

```text
mHasEntered = false
mWasInside = false
```

リセット後、カーソルがメインウインドウ内にあっても、最初のタイマー処理では侵入を記録するだけである。その後いったん外へ出てから再侵入した場合に、通常のアクティブ化処理が行われる。

### 入力文字列を空にした場合

入力文字列がある場合は候補欄を表示し、入力文字列がない場合は候補欄を非表示にしてメインウインドウを小さくする。

この縮小によって、縮小前はウインドウ内にあったカーソルが、縮小後のウインドウ領域の外へ移動する場合がある。この移動を通常の「カーソルがウインドウから退出した」と解釈すると、意図せずメインウインドウが非アクティブになる。

そのため、`LauncherMainWindow::OnEditCommandChanged()` で入力文字列が空になったことを検出した時点で、`mMouseoverActivateWindow.ResetState()` を呼び出している。

この処理は検索結果の非同期更新やウインドウのレイアウト変更を待たず、入力文字列が空になった直後に状態をリセットすることが重要である。

### タイマー停止時のリセット

`StopTimer()` でも `ResetState()` を呼び出す。設定を無効にした場合や、サイズ変更開始時にタイマーを停止した場合に、停止前のカーソル状態を次回の監視へ持ち越さないためである。

## ウインドウサイズ変更中の抑止

メインウインドウのサイズ変更中も、通常のメッセージループは動作している。そのため、サイズ変更中に `OnTimer()` が呼ばれ、カーソル位置の変化によって前景ウインドウを変更すると、サイズ変更操作を妨害する。

この問題を避けるため、`LauncherMainWindow` は次のメッセージを処理する。

- `WM_ENTERSIZEMOVE`: `MouseoverActivateWindow::Suspend()` を呼び出す
- `WM_EXITSIZEMOVE`: `MouseoverActivateWindow::Resume()` を呼び出す

`Suspend()` はタイマーを停止し、カーソル状態をリセットする。`Resume()` は監視停止状態を解除した後、設定値を再確認して必要ならタイマーを再開する。

サイズ変更開始・終了の通知は `LauncherMainWindow` から行うが、`MouseoverActivateWindow` は `LauncherMainWindow` の型や処理内容に依存しない。このため、サイズ変更処理とカーソル監視処理の責務を分離できている。

## 設定

設定画面の基本設定にある「カーソル位置によるアクティブ切替」のチェック状態を、次の設定キーで保存する。

```text
Soyokaze:IsMouseoverActivate
```

設定変更時には `AppPreference` のリスナー通知が発生し、タイマーの開始・停止が反映される。

## 保守時の注意点

- カーソル判定の間隔を変更する場合は、アクティブ切替の応答性とCPU負荷の両方を確認する。
- `mHasEntered` と `mWasInside` は意味が異なる。初回侵入を記録するために、両方を同時に単純な `isInside` 判定へ置き換えない。
- メインウインドウのサイズや表示部品を変更する処理では、カーソル領域が意図せず変化しないか確認する。
- ウインドウを縮小・移動・非表示にする新しい処理を追加する場合、必要に応じて `ResetState()` を呼び出す。
- サイズ変更処理中に `SetForegroundWindow()` や次のウインドウへの切り替えを行わない。
- `Suspend()` 中に設定が変更される可能性があるため、再開時は `Resume()` 内で設定値を再評価する。
- `GetNextHwnd()` は前景ウインドウの次にある表示中ウインドウを切り替え先としている。切り替え先の選定ロジックを変更する場合は、他アプリのウインドウやタスクバーとの関係を確認する。

## 動作確認項目

- 機能を有効にした状態で、カーソルを初めてメインウインドウ内へ移動しても不要な切替が起きない。
- メインウインドウ内へ入った後に外へ出ると、メインウインドウが非アクティブになる。
- 外へ出た後に再び入ると、メインウインドウがアクティブになる。
- メインウインドウをマウスドラッグでサイズ変更している間、カーソル監視による切替が起きない。
- 入力文字列を全削除してウインドウが縮小したとき、縮小に伴うカーソル移動だけでは非アクティブにならない。
- 入力文字列を全削除した後、カーソルを再度メインウインドウへ入れてから外へ出すと、通常どおり非アクティブになる。
- 設定を無効化するとタイマーが停止し、再度有効化すると監視が再開する。
